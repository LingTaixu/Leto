## Why Migrate from Next.js to Vite

IP Strategy is a **pure client-side DApp**: no SEO requirements, no server-side data fetching, and all state comes from the wallet and on-chain RPC. In such a scenario, Next.js's SSR capability is not only unused but also adds extra build complexity.

The post-migration stack is **Vite 7 + TanStack Router + Tailwind CSS 4** — lighter, faster, and closer to the essence of an SPA.

## File-based Routing: Directory as Routes

Routes are auto-generated by `@tanstack/router-plugin` scanning `src/pages`:

```
tanstackRouter({
  target: 'react',
  routesDirectory: './src/pages',
})
```

Each page exports a `Route` object with a clear convention:

```
export const Route = createFileRoute('/home/')({
  component: RouteComponent,
});

function RouteComponent() {
  return <div>...</div>;
}
```

Dynamic parameters use the `$` prefix (e.g. `/user/$id`), and directories starting with `-` are ignored (e.g. `-components`), which is ideal for placing page-private components nearby.

## Three High-frequency Changes During Migration

### 1. Route Navigation: useRouter → useNavigate

```
// Before migration
import { useRouter } from "next/navigation";
const router = useRouter();
router.push('/launch/create');

// After migration
import { useNavigate } from "@tanstack/react-router";
const navigate = useNavigate();
navigate({ to: '/launch/create' });
```

### 2. Utility library: lodash → es-toolkit

```
// Before migration
import { includes, reject } from "lodash";
// After migration
import { includes, reject } from "es-toolkit/compat";
```

The migration cost is extremely low, and the payoff is **significantly better bundle size and Tree-shaking performance** (lodash's CJS form is unfriendly to modern bundlers).

### 3. Directory convention: page.tsx → index.tsx

App Router's `page.tsx` is uniformly changed to `index.tsx`, aligning with TanStack Router's "directory as routes" model.

## Multi-chain Wallet Integration

The project supports both EVM and Solana, with two adapter stacks coexisting:

-   **EVM**: RainbowKit + wagmi + viem;
-   **Solana**: `@solana/wallet-adapter-*` + Reown AppKit Solana Adapter;
-   **Unified entry**: users select the target chain via `SelectChainModal`.

## Charts: TradingView Charting Library

K-line charts use TradingView's official library. Since it is not distributed via npm, extra handling is needed during migration:

```
# Copy static assets to src (Vite needs controllable asset paths)
./copy_charting_library_files.sh
```

This step can be covered by the `public` directory under Next.js, but in Vite the files must be explicitly copied, otherwise the build output will be missing files.

## Plugin Changes in Tailwind CSS 4

v4 replaces the PostCSS pipeline with a Vite plugin:

```
import tailwindcss from '@tailwindcss/vite';
// vite.config.ts
plugins: [tailwindcss(), react(), tsconfigPaths(), nodePolyfills()]
```

> Pitfall tip: after upgrading to v4, IDE class-name hints require explicitly importing Tailwind in each project's `global.css`; you cannot rely on global config alone.

## Two Key Points in Build Configuration

### Node Polyfill

The Web3 dependency chain heavily uses Node built-in modules (`buffer`, `stream`, `crypto`), so `vite-plugin-node-polyfills` must be added to run in the browser.

### Manual Code Splitting

```
manualChunks: {
  vendor: ['react', 'react-dom', 'wagmi'],
}
```

Large, infrequently-updated dependencies get their own chunk, avoiding users re-downloading the entire vendor bundle whenever business code changes.

## Sub-path Deployment

```
base: '/ipstrategy/',
```

With `base` set, the output can be deployed directly under a sub-path of the domain without rewriting asset references.

## Retrospective

The first principle of technology selection is **matching the scenario**. When a project does not need SSR, the type-safe routing, extremely fast HMR, and simpler build pipeline that Vite + TanStack Router provides is a more rational answer than "defaulting to Next.js".
